# JoyEngine 术语和概念

## 引擎的基本概述

JoyEngine 是一个基于 ECS 框架的游戏引擎。使用 C++/Woolang 进行游戏开发。

游戏开发期间，开发者所做的事情基本围绕着以下事项：

* 准备所需资源文件（纹理、模型、动画等）
* 编写 *组件*
* 在编辑器中使用特定的组件集合创建 *实体*，调整实体在 *世界* 范围内的位置以及实体的组件成员值
* 编写 *系统*，观察和修改特定的组件数据，实现游戏的逻辑

组件与系统主要以 Woolang *脚本* 的形式编写。

## 术语表

简单介绍一些关键的术语。每个词条都附有详细说明文档的链接。

#### ECS 术语

* 世界

世界（World）是容纳系统和组件实例的空间；引擎允许同时有多个世界实例存在。这些世界实例将 *并行* 地执行系统的逻辑。详细说明见 [world.md](world.md)。

* 组件

组件（Component）是纯粹的数据，组件本身不包含实际的游戏逻辑，但是在实际开发中，允许带有一些简单的、类似访问器的方法。详细说明见 [component.md](component.md)。

* 实体

实体（Entity）在引擎中是一个“不存在”的概念。实体是若干特定组件实例构成的集合——实体只是这样的集合关系本身。详细说明见 [entity.md](entity.md)。

当文档中提到实体一词时，其同义词是 `组件集合`。

* 预制体

预制体（Prefab）是作为模板的特殊实体，依照它可以实例化出组件构成相同的新实体。详细说明见 [prefab.md](prefab.md)。

* 系统

系统（System）是纯粹的逻辑集合。系统中的 *Update* 更新函数负责观察世界中的特定组件切片，并获取这些组件实例，读取或修改它们的成员数据。详细说明见 [system.md](system.md)。

* 切片

切片（Slice）是按组件类型过滤实体得到的子集，系统与渲染系统都通过切片定位自己感兴趣的实体（支持“必须包含 / 可有可无 / 多选一 / 排除”四种过滤条件）。详细说明见 [slice.md](slice.md)。

* 宇宙

宇宙（Universe，这个词有点中二……）是储存所有世界的容器，通常情况下，这个容器本身是一个单例。详细说明见 [universe.md](universe.md)。

#### 游戏术语

* 帧

JoyEngine 使用画面帧/逻辑帧同步。宇宙会负责对所有世界发起一轮*工作*调用。在工作调用（NORMAL_JOB_FOR_WORLDS）期间，执行所有的系统的更新逻辑。

综合来说，引擎完成一轮工作循环即被称为**一帧**。详细说明见 [frame.md](frame.md)。

* 工作

工作（Job）是 JoyEngine 的最基础的逻辑调用机制。引擎会在一帧中调用所有注册到宇宙中的工作——所有系统的逻辑更新也只是工作的一部分。详细说明见 [frame.md](frame.md)。

* 差异时间

差异时间（DeltaTime）是引擎提供的一种时间机制。笼统地说，差异时间指的是上一帧的开始时间，与当前帧开始时间的时间差。此时间由引擎负责计算，因为计算方法的不同，延伸出 *实时* 和 *平滑* 两种差异时间。宇宙还提供时间缩放（timescale）与最大差异时间（max deltatime）两种调节机制。详细说明见 [deltatime.md](deltatime.md)。

* 系统更新

更新（Update）是系统的逻辑函数，引擎将负责调用这些函数，一帧一次地执行游戏逻辑。系统的更新函数按执行时机分为 PRE_UPDATE、UPDATE 与 LATE_UPDATE 三个阶段。详细说明见 [system.md](system.md)。

* 脚本

脚本（Script）是用 Woolang 编写的游戏逻辑文件，脚本层 towoo 提供了 component! / system! / work! 等宏，用于在脚本中声明组件与系统。详细说明见 [script.md](script.md)。

* 变换

变换（Transform）用于表示实体的空间关系，即描述实体的绝对/相对位置信息，实体本身的旋转和缩放情况。当实体之间存在父子关系时，子实体的局部变换会经由父级逐级计算出最终的世界变换（Translation）。详细说明见 [transform.md](transform.md)。

* UI

UI，即 UserInterface。UI被设计用于在屏幕上以独特的定位方式，描述用户界面上的一些渲染内容。因为其独特的定位方式，它的渲染流程和普通实体并不一样。详细说明见 [ui.md](ui.md)。

* GUI

GUI 指引擎对接的即时模式界面后端（ImGui），主要用于编辑器与调试面板等引擎自身的界面，注意它和挂在实体上的 *UI* 组件是两个不同的概念。详细说明见 [gui.md](gui.md)。

* 渲染

渲染（Renderer）指的是将世界中，满足特定切片要求的组件集合，将相关的组件数据呈递并产生人眼可见的画面的过程。负责执行渲染的系统在引擎内部被称为 *渲染系统* 或者 *渲染管线*（渲染管线一词在不同领域有不同含义，这和 *可编程渲染管线* 一词情况类似，在文档中，上述词汇仅特指术语表中的含义）。

渲染的过程一般涉及到 *摄像机* 和待渲染的实体。详细说明见 [render.md](render.md)。

* 摄像机

摄像机（Camera）指的是带有特定的摄像机组件的实体；渲染系统会为每个摄像机渲染一次所有待渲染的实体。将渲染结果输出到屏幕，或者由 `RendToFramebuffer` 组件指示的目标缓冲区。详细说明见 [camera.md](camera.md)。

* 帧缓冲

帧缓冲（Framebuffer）是图形 API 层面的渲染目标，为摄像机挂载 `RendToFramebuffer` 组件后，该摄像机的渲染结果会写入指定的帧缓冲而不是屏幕。详细说明见 [framebuffer.md](framebuffer.md)。

* 射线

射线（Ray）由起点与方向构成，可以由摄像机的投影参数和屏幕坐标直接构造，常用于拾取等交互逻辑。详细说明见 [ray.md](ray.md)。

* 光照

光照（Light）通过光照组件描述场景中的光源，JoyEngine 内置 2D 光照系统（Light2D），支持点光、平行光与多种阴影。详细说明见 [light.md](light.md)。

* 动画

动画（Animation）是一种随着时间变化而改变实体组件数据，并借此最终影响渲染结果，借助人体的视觉暂留效应产生独特视觉效果的机制。详细说明见 [animation.md](animation.md)。

* 粒子

粒子（Particle）用于模拟火焰、烟雾等大量细小对象的运动与消亡，粒子发射器（Emitter）组件描述粒子的发射与生命周期行为，模拟由引擎的粒子系统完成。详细说明见 [particle.md](particle.md)。

* 物理

物理（Physics）通过物理引擎，模拟实体如同现实中的物体一般发生受力、碰撞、摩擦和反弹等物理现象时的变换变化。

JoyEngine 通过 Box2D 模拟 2D 物理。详细说明见 [physics.md](physics.md)。

* 音频

音频（Audio）能够播放音频，并模拟发声源出于特定场景下的声音效果。详细说明见 [audio.md](audio.md)。

* 瓦片地图

瓦片地图（TileMap）是一种快速绘制 2D 场景的机制。详细说明见 [tilemap.md](tilemap.md)。

* 输入

输入（Input）子系统负责收集键盘、鼠标与手柄的输入状态，供游戏逻辑读取；虚拟手柄（VirtualGamepad）组件可以把键盘按键映射为手柄按键。详细说明见 [input.md](input.md)。

#### 资源术语

* 纹理

纹理（Texture）是承载像素数据的图像资源，渲染时被采样到几何表面，支持 2D 纹理与纹理数组等形式。详细说明见 [texture.md](texture.md)。

* 着色器

着色器（Shader）描述顶点变换与像素着色的方式；引擎没有独立的“材质”概念，纹理采样、混合模式等均由着色器承担。详细说明见 [shader.md](shader.md)。

* 网格

网格（Mesh）是参与渲染的几何数据（顶点与索引的集合），由模型文件加载，也可以程序化创建。详细说明见 [mesh.md](mesh.md)。

* 缓存

缓存（Cache，je4cache）是资源的预处理产物：原始资源在首次加载时被转换为更适合运行时读取的格式，原始资源变化后缓存会自动重建。详细说明见 [cache.md](cache.md)。

* 资源镜像

资源镜像（fimg）是引擎的发布打包格式，把项目资源、编译后的脚本与着色器缓存打包到一组文件中（详见 `doc/fimg/fimg_format.md`）。详细说明见 [fimg.md](fimg.md)。

#### 引擎与扩展

* 入口

入口是引擎启动时执行的首个脚本（`builtin/main.wo`）；找不到游戏入口时，引擎会转而启动内置的编辑器。详细说明见 [entry.md](entry.md)。

* 编辑器

编辑器（Editor）是随引擎发布的可视化编辑工具，本身也用 Woolang 编写（文档见 `doc/editor`）。详细说明见 [editor.md](editor.md)。

* 模块

模块（Module，`*.je4module`）是以 C++ 编写、静态链接进引擎的可选原生扩展。详细说明见 [module.md](module.md)。

* 包

包（Package）是 Woolang 语言的依赖管理单位，由包管理器 baozi 管理（`baozi.toml`）。详细说明见 [package.md](package.md)。

#### 数学概念

* 标量和矢量

标量指的是只有大小的量，矢量既有大小，也有方向。

JoyEngine 提供 ivec2，vec2，vec3，vec4 作为矢量类型。详细说明见 [math.md](math.md)。

* 矩阵

矩阵（Matrix）描述线性变换，JoyEngine 使用 4×4 矩阵（mat4）表示变换与投影，如物体到世界矩阵、摄像机投影矩阵。详细说明见 [math.md](math.md)。

* 四元数

四元数是一种表示三维空间中旋转的常用形式。

JoyEngine 提供 quat 四元数类型。详细说明见 [math.md](math.md)。

* 颜色

颜色（color）以 RGBA 四个分量按线性空间存储，通常取值 0~1，RGB 分量允许超过 1 以表示 HDR。详细说明见 [math.md](math.md)。

#### 关键词

* 数据

在 JoyEngine 中，数据是与逻辑相对应的概念。组件被设计用于容纳数据——组件本身也是数据。数据是一种状态，JoyEngine 的设计原则中，总是处理状态而不处理事件。详细说明见 [data-logic.md](data-logic.md)。

* 逻辑

在 JoyEngine 中，逻辑是与数据相对应的概念。逻辑读取数据、处理数据以及更新数据。纯粹的逻辑本身应当是无副作用的——它只描述数据在输入之后被怎样处理和更新这一过程。详细说明见 [data-logic.md](data-logic.md)。
